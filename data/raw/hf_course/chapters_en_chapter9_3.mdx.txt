Understanding the Interface class.

In this section, we will take a closer look at the <code> class, and understand the main parameters used to create one.

How to create an Interface.

You'll notice that the <code> class has 3 required parameters:

<code>.

These parameters are:

<code>: the prediction function that is wrapped by the Gradio interface. This function can take one or more parameters and return one or more values.

<code>: the input component type(s). Gradio provides many pre-built components such as<code> or <code>.

<code>: the output component type(s). Again, Gradio provides many pre-built components e.g. <code> or <code>.

For a complete list of components, see the Gradio docs . Each pre-built component can be customized by instantiating the class corresponding to the component.

For example, as we saw in the previous section, instead of passing in <code> to the <code> parameter, you can pass in a <code> component to create a textbox with 7 lines and a label.

The <code> method.

So far, we have used the <code> method to launch the interface, but we haven't really discussed what it does.

By default, the <code> method will launch the demo in a web server that is running locally. If you are running your code in a Jupyter or Colab notebook, then Gradio will embed the demo GUI in the notebook so you can easily use it.

You can customize the behavior of <code> through different parameters:

<code> - whether to display the interface inline on Python notebooks.

<code> - whether to automatically launch the interface in a new tab on the default browser.

<code> - whether to create a publicly shareable link from your computer for the interface. Kind of like a Google Drive link!
