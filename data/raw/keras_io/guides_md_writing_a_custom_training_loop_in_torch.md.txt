Introduction.

Keras provides default training and evaluation loops, <code> and <code>. Their usage is covered in the guide Training & evaluation with the built-in methods.

If you want to customize the learning algorithm of your model while still leveraging the convenience of <code> (for instance, to train a GAN using <code>), you can subclass the <code> class and implement your own <code> method, which is called repeatedly during <code>.

Now, if you want very low-level control over training & evaluation, you should write your own training & evaluation loops from scratch. This is what this guide is about.

You retrieve the gradients for the variables via <code>, called on each trainable variable.

You update your variables via <code>, which must be called in a <code> scope.

Also, a big gotcha: while all NumPy/TensorFlow/JAX/Keras APIs as well as Python <code> APIs use the argument order convention <code> (reference values first, predicted values second), PyTorch actually uses <code> for its losses. So make sure to invert the order of <code> and <code>.
