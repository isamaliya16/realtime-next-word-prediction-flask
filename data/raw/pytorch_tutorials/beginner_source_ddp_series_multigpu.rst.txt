<code> is a PyTorch wrapper around Python's native multiprocessing.

The distributed process group contains all the processes that can communicate and synchronize with each other.

Constructing the process group.

First, before initializing the group process, call set_device, which sets the default GPU for each process. This is important to prevent hangs or excessive memory utilization on <code>.

The process group can be initialized by TCP (default) or from a shared file-system. Read more on process group initialization.

initprocessgroup initializes the distributed process group.

Distributing input data.

DistributedSampler chunks the input data across all distributed processes.

The DataLoader combines a dataset and a sampler, and provides an iterable over the given dataset.

Each process will receive an input batch of 32 samples; the effective batch size is <code>, or 128 when using 4 GPUs.

Calling the <code> method on the <code> at the beginning of each epoch is necessary to make shuffling work properly across multiple epochs. Otherwise, the same ordering will be used in each epoch.

Saving model checkpoints.

We only need to save model checkpoints from one process. Without this condition, each process would save its copy of the identical mode. Read more on saving and loading models with DDP here.
