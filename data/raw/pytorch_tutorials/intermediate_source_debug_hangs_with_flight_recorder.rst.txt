Debugging Hangs with Flight Recorder Using TorchComms and Debug Server.

TorchComms is a Python library that provides a high-level communicator abstraction over PyTorch's distributed backends (NCCL, Gloo, etc.). It wraps collective operations with a hook system that lets you attach instrumentation, such as logging, profiling, or recording, without modifying application code. For more information, see TorchComms Documentation.

The TorchComms Flight Recorder is one such hook (<code>). It maintains a fixed-size ring buffer that silently records every collective operation issued through a TorchComms communicator that captures the operation type, sequence number, tensor shapes, execution state, and the Python stack trace at the call site. For a reference on the Flight Recorder, see Flight Recorder Hook in TorchComms.

The Debug Server (<code>) runs an HTTP server on each rank that can periodically dump Flight Recorder snapshots and Python stack traces to disk. For full API documentation on the debug server, its endpoints and periodic dumping, see the torch.distributed debug HTTP server docs.

This tutorial walks you through a concrete example: a two-rank job where one rank hangs before a collective, and shows how to use the Flight Recorder and Debug Server to diagnose it step by step.

When periodic dumping is enabled on the debug server, each dump cycle produces two kinds of output:

Aggregated text files (<code>) — the frontend on rank 0 fetches FR data from all ranks and writes a human-readable table.

Per-rank pickle files (<code>) — each rank's worker server writes its own pickle trace. These can be fed to the FR CLI (<code>) for automated cross-rank mismatch detection.

Conclusion.

In this tutorial, you have learned how to use the TorchComms Flight Recorder and the Debug Server to diagnose a single-rank hang in a distributed PyTorch job. By examining the aggregated text dumps, per-rank pickle traces, and stack trace snapshots, you identified which collective was stuck, which rank failed to participate, and the exact line of code responsible for the hang. You can apply this same workflow to debug real-world distributed training hangs — replace the simulated <code> with whatever your job is actually stuck on, and the Flight Recorder will show you where ranks diverged.
