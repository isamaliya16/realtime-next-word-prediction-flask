Introduction to <code> Author: William Wen.

<code> is the new way to speed up your PyTorch code! <code> makes PyTorch code run faster by JIT-compiling PyTorch code into optimized kernels, while requiring minimal code changes.

<code> accomplishes this by tracing through your Python code, looking for PyTorch operations. Code that is difficult to trace will result a graph break, which are lost optimization opportunities, rather than errors or silent incorrectness.

<code> is available in PyTorch 2.0 and later.

This introduction covers basic <code> usage and demonstrates the advantages of <code> over our previous PyTorch compiler solution, TorchScript.

For an end-to-end example on a real model, check out our end-to-end torch.compile tutorial.

Benefits over TorchScript.

Why should we use <code> over TorchScript? Primarily, the advantage of <code> lies in its ability to handle arbitrary Python code with minimal changes to existing code.

Compare to TorchScript, which has a tracing mode (<code>) and a scripting mode (<code>). Tracing mode is susceptible to silent incorrectness, while scripting mode requires significant code changes and will raise errors on unsupported Python code.

For example, TorchScript tracing silently fails on data-dependent control flow (the <code> line below) because only the actual control flow path is traced. In comparison, <code> is able to correctly handle it.

TorchScript scripting can handle data-dependent control flow, but it can require major code changes and will raise errors when unsupported Python is used.

Graph Breaks The graph break is one of the most fundamental concepts within <code>. It allows <code> to handle arbitrary Python code by interrupting compilation, running the unsupported code, then resuming compilation. The term "graph break" comes from the fact that <code> attempts to capture and optimize the PyTorch operation graph. When unsupported Python code is encountered, then this graph must be "broken". Graph breaks result in lost optimization opportunities, which may still be undesirable, but this is better than silent incorrectness or a hard crash.
