DebugMode: Recording Dispatched Operations and Numerical Debugging.

Overview.

<code> (torch.utils.debugmode.DebugMode) is a <code> that intercepts PyTorch runtime calls and emits a hierarchical log of operations. It is particularly useful when you need to understand what actually runs, both in eager mode and under <code> or when you need to pinpoint numerical divergence between two runs.

Key capabilities:

Runtime logging – Records dispatched operations and TorchInductor compiled Triton kernels.

Tensor hashing – Attaches deterministic hashes to inputs/outputs to enable diffing runs to locate numerical divergences.

Dispatch hooks – Allows registration of custom hooks to annotate calls.

Getting more metadata.

For most investigations, you'll want to enable stack traces, tensor IDs, and tensor hashing. These features provide metadata to correlate operations back to model code.

<code> decorates the log with hashes for every call. The <code> hash function uses <code>, which returns 0 for tensors whose elements are all the same. The <code> hash function uses <code> with <code>. With both these functions, especially <code>, tensor closeness in numerics is related to hash closeness, so it's rather interpretable. The default <code> is <code>.

Each line follows <code>. When <code> is enabled, tensors are suffixed with <code> and DTensors are labeled <code>.

Log Triton kernels.

Though Triton kernels are not dispatched, DebugMode has custom logic that logs their inputs and outputs.

Inductor-generated Triton kernels show up with a <code> prefix. Pre/post hash annotations report buffer hashes around each kernel call, which is helpful when isolating incorrect kernels.

Custom dispatch hooks.

Hooks allow you to annotate each call with custom metadata such as GPU memory usage. <code> returns a mapping that is rendered inline with the debug string.

Module boundaries.

<code> inserts <code> markers that show which module executed each set of operations. As of PyTorch 2.10 it only works in eager mode, but support for compiled modes is under development.

Conclusion.

In this tutorial, we saw how DebugMode gives you a lightweight, runtime-only view of what PyTorch actually executed, whether you are running eager code or compiled graphs. By layering tensor hashing, Triton logging, and custom dispatch hooks you can quickly track down numerical differences. This is especially helpful in debugging bit-wise equivalence between runs.
