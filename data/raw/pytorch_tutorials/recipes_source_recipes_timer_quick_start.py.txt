A/B testing with <code>.

One of the most useful features of instruction counts is they allow fine grained comparison of computation, which is critical when analyzing performance.

To see this in action, lets compare our multiplication of two size 128 Tensors with a {128} x {1} multiplication, which will broadcast the second Tensor: result = {a0 b0, a1 b0, ..., a127 b0}.

Often we want to A/B test two different environments. (e.g. testing a PR, or experimenting with compile flags.) This is quite simple, as <code>, <code>, and Measurement are all pickleable. Simply save measurements from each environment, and load them in a single process for analysis.

Wrapping up.

In summary, use <code> to collect wall times. If timing variation is too high, increase <code>, or move to C++ snippets if convenient.

For fine grained analysis, use <code> to measure instruction counts and <code> to slice-and-dice them.
