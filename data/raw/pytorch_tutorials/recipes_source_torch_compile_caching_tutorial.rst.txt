Introduction.

PyTorch Compiler provides several caching offerings to reduce compilation latency. This recipe will explain these offerings in detail to help users pick the best option for their use case.

Check out Compile Time Caching Configurations for how to configure these caches.

Also check out our caching benchmark at PT CacheBench Benchmarks.

Modular caching of <code>, <code>, and <code>.

The aforementioned <code> is composed of individual components that can be used without any user intervention. By default, PyTorch Compiler comes with local on-disk caches for <code>, <code>, and <code>. These caches include:

<code>: A cache of graph-based IR components used in compilation.

<code>: A cache of Triton-compilation results, including <code> files generated by <code> and other caching artifacts.

<code>: A bundle of <code> and <code> cache.

<code>: A cache of joint graph artifacts.

<code>: A cache of dynamic shape decisions to reduce number of recompilations.

AutotuningCache:

<code> generates <code> kernels and benchmarks them to select the fastest kernels.

<code>'s built-in <code> caches these results.

Remote Caching.

We also provide a remote caching option for users who would like to take advantage of a Redis based cache. Check out Compile Time Caching Configurations to learn more about how to enable the Redis-based caching.

Conclusion In this recipe, we have learned that PyTorch Inductor's caching mechanisms significantly reduce compilation latency by utilizing both local and remote caches, which operate seamlessly in the background without requiring user intervention.
