Input function.

This tutorial uses the MNIST dataset from TensorFlow Datasets. The code here is similar to the multi-GPU training tutorial with one key difference: when using Estimator for multi-worker training, it is necessary to shard the dataset by the number of workers to ensure model convergence. The input data is sharded by worker index, so that each worker processes <code> distinct portions of the dataset.

Another reasonable approach to achieve convergence would be to shuffle the dataset with distinct seeds at each worker.

Optimize training performance.

You now have a model and a multi-worker capable Estimator powered by <code>. You can try the following techniques to optimize performance of multi-worker training:

Increase the batch size: The batch size specified here is per-GPU. In general, the largest batch size that fits the GPU memory is advisable.

Cast variables: Cast the variables to <code> if possible. The official ResNet model includes an example of how this can be done.

Use collective communication: <code> provides multiple collective communication implementations.

<code> implements ring-based collectives using gRPC as the cross-host communication layer.

<code> uses Nvidia's NCCL to implement collectives.

<code> defers the choice to the runtime.

The best choice of collective implementation depends upon the number and kind of GPUs, and the network interconnect in the cluster. To override the automatic choice, specify a valid value to the <code> parameter of <code>'s constructor, e.g. <code>.
