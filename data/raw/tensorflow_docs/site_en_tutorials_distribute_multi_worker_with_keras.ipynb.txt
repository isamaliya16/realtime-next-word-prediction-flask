Overview.

This tutorial demonstrates how to perform multi-worker distributed training with a Keras model and the <code> API using the <code> API. With the help of this strategy, a Keras model that was designed to run on a single-worker can seamlessly work on multiple workers with minimal code changes.

To learn how to use the <code> with Keras and a custom training loop, refer to Custom training loop with Keras and MultiWorkerMirroredStrategy.

This tutorial contains a minimal multi-worker example with two workers for demonstration purposes.

Choose the right strategy.

Before you dive in, make sure that <code> is the right choice for your accelerator(s) and training. These are two common ways of distributing training with data parallelism:

Synchronous training, where the steps of training are synced across the workers and replicas, such as <code>, <code>, and <code>. All workers train over different slices of input data in sync, and aggregating gradients at each step.

Asynchronous training, where the training steps are not strictly synced, such as <code>. All workers are independently training over the input data and updating variables asynchronously.

If you are looking for multi-worker synchronous training without TPU, then <code> is your choice. It creates copies of all variables in the model's layers on each device across all workers. It uses <code>, a TensorFlow op for collective communication, to aggregate gradients and keeps the variables in sync. For those interested, check out the <code> parameter for the collective implementation options.

For an overview of <code> APIs, refer to Distributed training in TensorFlow.

Fault tolerance.

In synchronous training, the cluster would fail if one of the workers fails and no failure-recovery mechanism exists.

Using Keras with <code> comes with the advantage of fault tolerance in cases where workers die or are otherwise unstable. You can do this by preserving the training state in the distributed file system of your choice, such that upon a restart of the instance that previously failed or preempted, the training state is recovered.

When a worker becomes unavailable, other workers will fail (possibly after a timeout). In such cases, the unavailable worker needs to be restarted, as well as other workers that have failed.

Note: Previously, the <code> callback provided a mechanism to restore the training state upon a restart from a job failure for multi-worker training. The TensorFlow team is introducing a new <code> callback, which also adds the support to single-worker training for a consistent experience, and removed the fault tolerance functionality from existing <code> callback. From now on, applications that rely on this behavior should migrate to the new <code> callback.

The <code> callback.

<code> callback no longer provides fault tolerance functionality, please use <code> callback instead.

The <code> callback can still be used to save checkpoints. But with this, if training was interrupted or successfully finished, in order to continue training from the checkpoint, the user is responsible to load the model manually.

Optionally, users can choose to save and restore model/weights outside <code> callback.

Model saving and loading.

To save your model using <code> or <code>, the saving destination needs to be different for each worker.

For non-chief workers, you will need to save the model to a temporary directory.

For the chief, you will need to save to the provided model directory.

The temporary directories on the worker need to be unique to prevent errors resulting from multiple workers trying to write to the same location.

The model saved in all the directories is identical, and typically only the model saved by the chief should be referenced for restoring or serving.

You should have some cleanup logic that deletes the temporary directories created by the workers once your training has completed.

The reason for saving on the chief and workers at the same time is because you might be aggregating variables during checkpointing, which requires both the chief and workers to participate in the allreduce communication protocol. On the other hand, letting chief and workers save to the same model directory will result in errors due to contention.

The <code> callback.

The <code> callback provides the fault tolerance functionality by backing up the model and current training state in a temporary checkpoint file under <code> argument to <code>.

Note: In Tensorflow 2.9, the current model and the training state is backed up at epoch boundaries. In the <code> version and from TensorFlow 2.10, the <code> callback can back up the model and the training state at epoch or step boundaries. <code> accepts an optional <code> argument. <code> accepts either <code> or an <code> value. If <code> is set to <code> the model is backed up after every epoch. If <code> is set to an integer value greater than <code>, the model is backed up after every <code> number of batches.

Once the jobs get interrupted and restarted, the <code> callback restores the last checkpoint, and you can continue training from the beginning of the epoch and step at which the training state was last saved.

To use it, provide an instance of <code> at the <code> call.

With <code>, if a worker gets interrupted, the whole cluster will pause until the interrupted worker is restarted. Other workers will also restart, and the interrupted worker will rejoin the cluster. Then, every worker will read the checkpoint file that was previously saved and pick up its former state, thereby allowing the cluster to get back in sync. Then, the training will continue. The distributed dataset iterator state will be re-initialized and not restored.

The <code> callback uses the <code> to save and restore the training state, which generates a file called checkpoint that tracks existing checkpoints together with the latest one. For this reason, <code> should not be re-used to store other checkpoints in order to avoid name collision.

Currently, the <code> callback supports single-worker training with no strategy—<code>—and multi-worker training with <code>.
