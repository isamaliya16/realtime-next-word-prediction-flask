The TFRecord format is a simple format for storing a sequence of binary records.

Protocol buffers are a cross-platform, cross-language library for efficient serialization of structured data.

Protocol messages are defined by <code> files, these are often the easiest way to understand a message type.

The <code> message (or protobuf) is a flexible message type that represents a <code> mapping. It is designed for use with TensorFlow and is used throughout the higher-level APIs such as TFX.

This notebook demonstrates how to create, parse, and use the <code> message, and then serialize, write, and read <code> messages to and from <code> files.

Note: While useful, these structures are optional. There is no need to convert existing code to use TFRecords, unless you are using tf.data and reading data is still the bottleneck to training. You can refer to Better performance with the tf.data API for dataset performance tips.

Note: In general, you should shard your data across multiple files so that you can parallelize I/O (within a single host or across multiple hosts). The rule of thumb is to have at least 10 times as many files as there will be hosts reading data. At the same time, each file should be large enough (at least 10 MB+ and ideally 100 MB+) so that you can benefit from I/O prefetching. For example, say you have <code> GB of data and you plan to train on up to <code> hosts. Ideally, you should shard the data to ~<code> files, as long as ~<code> is 10 MB+ (and ideally 100 MB+). If it is less than that, you might need to create fewer shards to trade off parallelism benefits and I/O prefetching benefits.

TFRecords format details.

A TFRecord file contains a sequence of records. The file can only be read sequentially.

Each record contains a byte-string, for the data-payload, plus the data-length, and CRC-32C (32-bit CRC using the Castagnoli polynomial) hashes for integrity checking.

Each record is stored in the following formats:

uint64 length uint32 maskedcrc32oflength byte data[length] uint32 maskedcrc32ofdata.

The records are concatenated together to produce the file. CRCs are described here, and the mask of a CRC is:

masked_crc = ((crc >> 15) | (crc << 17)) + 0xa282ead8ul.

Note: There is no requirement to use <code> in TFRecord files. <code> is just a method of serializing dictionaries to byte-strings. Any byte-string that can be decoded in TensorFlow could be stored in a TFRecord file. Examples include: lines of text, JSON (using <code>), encoded image data, or serialized <code> (using <code>/<code>). See the <code> module for more options.
